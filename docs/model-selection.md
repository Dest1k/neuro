# Модели, кеш и стоимость исполнения

Обновлено в итерации 10/10 · 12 ноября 2026 года

## Текущее решение

**Предварительный основной исполнитель — `minimax/minimax-m3`: владелец решил
дать MiniMax второй шанс.** В конфигурации это
`provisional_user_selected_retrial`. Это выбор для ограниченной повторной
проверки на полезных задачах, а не вывод из нового сравнительного теста CUDA.
Маршрут, модель за этим именем, формат usage и реальный кеш-биллинг ещё не
подтверждены. Резервирование и итоговый бюджетный учёт поэтому идут **без скидки
за кеш**, даже если API сообщает прочитанные из кеша токены.

`openai/gpt-6.1-sol` остаётся явно настраиваемым резервным исполнителем. Он
**выключен по умолчанию**. После включения действуют отдельные пределы: три
зарезервированных/выполненных вызова и $0.50 на сессию, внутри общих $5 на сессию
и $25 на кампанию. Вызов резервной модели требует явного точного `model_id`;
модуль сам не переключает модели и не повторяет запросы. Каждый оплачиваемый
повтор получает собственную reservation.

Sonnet и Opus — кандидаты для отдельных ревью. Kimi — дополнительный кандидат,
если основной выбор не сойдётся по качеству или маршруту. DeepSeek из текущей
таблицы пока не выбран основным: сведения о кеше отсутствуют. Результаты прежнего
теста другого маршрута не доказывают условия текущего.

## Откуда взяты цифры

Источник всех цен ниже — **таблица реселлера, присланная пользователем
11.11.2026**. URL провайдера, доступность маршрутов, точная идентичность моделей,
тарифные TTL, поддержка DSH и реальный биллинг не проверены. API-запросы в этой
итерации не выполнялись. Официальные цены производителей не подменяют эти цены.

Файл `configs/model-prices.json` содержит выбранное подмножество исходной таблицы.
Строки маршрутов сохраняются дословно; короткие псевдонимы не разрешаются.
`null` означает «неизвестно», а не нулевую цену. Для Kimi сохранена исходная
пометка `262K`; точное количество доступных токенов из неё не выдумано.

Все суммы — USD за 1 000 000 токенов.

| Маршрут из таблицы | Вход | Выход | Чтение кеша | Запись кеша без указанного TTL |
|---|---:|---:|---:|---:|
| `openai/gpt-6.1-sol` | 0.281 | 1.403 | неизвестно | неизвестно |
| `minimax/minimax-m3` | 0.077 | 0.310 | 0.0154 = 0.2× входа | 0.077 = 1× входа |
| `anthropic/claude-sonnet-5` | 0.310 | 1.548 | 0.031 = 0.1× входа | 0.4278 = 1.38× входа |
| `anthropic/claude-opus-5` | 0.774 | 3.870 | 0.0774 = 0.1× входа | 0.9675 = 1.25× входа |
| `moonshotai/kimi-k2.7-code` | 0.116 | 0.542 | 0.02436 = 0.21× входа | 0.116 = 1× входа |

Указанный общий множитель записи не устанавливает тариф отдельного TTL. В
манифесте цены записи `5m` и `1h` намеренно неизвестны. Если usage явно сообщает
такой класс записи, счётчик остановит расчёт до появления цены именно этого
класса. Переносить официальный тариф Anthropic на неизвестного реселлера нельзя.

## Сопоставимый сценарий расходов

Условный объём: **100 вызовов × 64 000 входных и 2 000 выходных токенов**,
то есть 6.4 млн входа и 0.2 млн выхода. Выход должен включать весь оплачиваемый
reasoning. Это пример арифметики, не прогноз числа вызовов или срока проекта.

В столбце «90% чтения» 5.76 млн токенов действительно прочитаны из кеша,
0.64 млн оплачены как обычный вход. Последний столбец показывает вариант,
где эти 0.64 млн вместо обычного входа оплачены как запись без указанного TTL.
Первые холодные запросы и дальнейшие прогревы должны укладываться в эти общие
счётчики; 90% не обещается заранее.

| Маршрут | Кеш выключен, весь вход обычный | 90% чтения + обычный остаток | 90% чтения + остаток как запись |
|---|---:|---:|---:|
| Sol | $2.079000 | скидка неизвестна: $2.079000 | цена записи неизвестна |
| MiniMax M3 | $0.554800 | $0.199984 | $0.199984 |
| Sonnet 5 | $2.293600 | $0.686560 | $0.761952 |
| Opus 5 | $5.727600 | $1.715184 | $1.839024 |
| Kimi K2.7 Code | $0.850800 | $0.3229536 | $0.3229536 |
| DeepSeek V4.1 Flash | $0.576200 | скидка неизвестна: $0.576200 | цена записи неизвестна |

Вариант с включённым кешем и нулевым числом чтений может оказаться дороже
выключенного кеша из-за платных записей. Первый столбец не скрывает эту наценку:
он моделирует именно обычный вход, без записей.

При таком объёме MiniMax с 90% чтения стоит примерно в 10.4 раза дешевле Sol
без подтверждённой скидки. Это не означает, что можно бездумно разрешить ему
в десять раз больше попыток: последующие запросы могут расти, отладка занимает
время, а неверный код требует проверки. Нужна **стоимость принятого изменения**:
все оплаченные попытки, исправления и ревью до прохождения критерия результата.
Быстрый поток токенов и красивый отчёт сами по себе результата не подтверждают.

## Как проверить кеш перед длительной работой

1. Зафиксировать точный route, формат API и версию клиента. Получить актуальные
   цены от провайдера и указание, как отражаются записи и TTL.
2. Отправить несколько запросов с достаточно длинным неизменным началом, затем
   воспроизвести настоящий цикл с tool results и паузой на компиляцию. Один
   искусственный повтор не доказывает кеш всего агентного процесса.
3. Сопоставить финальные usage-счётчики с изменением баланса. Считать долю попаданий
   по токенам, а не по количеству запросов. Учитывать записи и reasoning.
4. На одинаковых небольших задачах сравнить принятые изменения, потраченную сумму,
   число исправлений и время. CUDA-задача должна проверяться сборкой и эталонным
   результатом на целевом оборудовании.

Системные инструкции и определения инструментов стоит держать стабильными.
Переменные отметки времени, новые результаты и новую задачу следует добавлять
после повторяемого контекста. Это повышает вероятность повторного использования,
но не заменяет измерения конкретного маршрута.

Не нужно регулярно посылать платные запросы только ради сохранения кеша во время
долгого GPU-теста. Сначала сравниваются стоимость нового прогрева, документированного
длинного TTL и таких поддерживающих запросов. В этой итерации ни один из этих
режимов не включается.

## Что реализовано в `neuroctl.cost`

Это самостоятельный модуль Python standard library, без SDK, сети и интеграции
с DSH. Он принимает один полный финальный snapshot usage и вычисляет оценку.
Сам он не запускает модель, не хранит API-ключи и не является сверкой счёта.
В итерации 6 рядом добавлен `neuroctl.budget`: он использует этот нормализатор
в транзакционной границе резервирования, описанной ниже. Подключение реального
клиента и сбор финального usage остаются обязанностью конкретного DSH-адаптера;
вывод `billing_verified` у обоих модулей всегда `false`.

Публичные функции:

```python
from neuroctl.cost import load_pricing, normalize_usage, estimate_cost

pricing = load_pricing("configs/model-prices.json", "minimax/minimax-m3")
usage = normalize_usage(final_response, api_format="openai")
result = estimate_cost(usage, pricing)
```

`final_response` — уже полученный JSON-объект с `usage` либо сам объект usage.
Результат сериализуется через `json.dumps`; суммы возвращаются десятичными строками,
а не числами с двоичной погрешностью. Ключ `total_cost_usd` содержит сумму,
`cost_usd` — компоненты. Исходный текст запросов, ответы модели, ключи и заголовки
не копируются в результат.

### Правила нормализации

| Формат | Как считается полный вход | Подтверждение чтения кеша |
|---|---|---|
| OpenAI Chat Completions | `prompt_tokens` уже включает кеш | `prompt_tokens_details.cached_tokens` |
| OpenAI Responses | `input_tokens` уже включает кеш | `input_tokens_details.cached_tokens` |
| Anthropic Messages | `input_tokens + cache_read_input_tokens + cache_creation_input_tokens` | `cache_read_input_tokens` |

Поддержаны значения `api_format`: `openai`, `openai_chat`, `openai_responses`,
`anthropic`, `auto`. Если `auto` не может различить смысл `input_tokens`, требуется
явный формат. Смешанные поля разных форматов не считаются взаимозаменяемыми.

Эта таблица описывает **исходный ответ API**, а не произвольный нормализованный
объект DSH. В нормализованном журнале `inputTokens` может обозначать только
некешированную часть, а `cacheReadTokens` — отдельную часть входа. Нельзя просто
переименовать `inputTokens` в OpenAI `prompt_tokens` или считать по нему размер
следующего запроса. Сначала проследите преобразование в установленном клиенте и
проверьте его на полном финальном ответе; документируйте, какие поля уже включают
кеш и reasoning. Оценка кеш-попадания и предел 64 000 относятся ко всему входу,
включая сохранённый префикс, инструменты и их результаты. Историческое название
API или прежний успешный cache hit не устанавливают семантику текущего маршрута.

Поведение в спорных случаях:

- **Нет метаданных кеша:** статус `UNKNOWN`, скидка не применяется. У OpenAI
  полный вход известен и оплачивается целиком как обычный. У Anthropic отсутствие
  отдельных счётчиков означает, что часть общего входа может быть вообще не
  сообщена: возвращается сумма для наблюдаемых токенов с
  `accounting_complete=false`. Её нельзя выдавать за потолок расходов.
- **Чтение сообщено, цена неизвестна:** применяется обычная цена входа, добавляется
  явное допущение. Это не подтверждение фактической цены провайдера.
- **Запись сообщена, цена её класса неизвестна:** `PricingError`; нулевую цену или
  произвольный множитель счётчик не придумывает.
- **Известен TTL:** `ephemeral_5m_input_tokens` и `ephemeral_1h_input_tokens`
  раскладывают общий счётчик записей, не добавляются к нему второй раз. Если оба
  поля присутствуют без общего счётчика, их сумма служит известным итогом.
- **Reasoning:** не прибавляется к выходу повторно. Передаётся полный оплачиваемый
  output, который сообщает провайдер; вложенный счётчик reasoning уже входит в него.
- **Повреждённые данные:** отрицательные, булевы, дробные, строковые и `null`
  значения token-счётчиков отклоняются. Противоречащие друг другу итоги,
  кеш больше полного входа и неизвестные положительные TTL-классы тоже отклоняются.
- **Потоковые события:** частичные фрагменты не принимаются как готовая стоимость.
  Для нестандартных полей реселлера нужен документированный адаптер; он пока не
  реализован и не имитируется.

Нулевые суммы возможны только для явно сообщённого нулевого объёма или явно заданной
нулевой цены. Отсутствующая цена записи никогда не становится нулевой. Неполный
Anthropic usage даже с нулевыми наблюдаемыми токенами остаётся неполным.

## Граница бюджета в `neuroctl.budget`

Модуль сохраняет reservations и завершённый учёт в SQLite. Установка дополнительных
Python-пакетов не нужна. Все изменения проходят через `BEGIN IMMEDIATE` и
`synchronous=FULL`; разные процессы используют один и тот же локальный файл.
Денежные значения хранятся десятичными строками и складываются с точной Decimal
арифметикой. SQLite `REAL`, дробные JSON-числа и округление до центов не используются.

### Действующие пределы

| Ограничение | Значение |
|---|---:|
| Общий вход одного запроса, включая системный текст, tools и кеш | 64 000 токенов |
| Общий оплачиваемый выход, включая reasoning | 8 000 токенов |
| Reservations и выполненные попытки в одной сессии | 200 |
| Все модели вместе, одна сессия | $5 |
| Все сессии одной кампании | $25 |
| Sol после явного включения, внутри общих пределов | 3 вызова и $0.50 на сессию |
| Скидка за кеш при бюджетном учёте | отсутствует |

Для MiniMax максимальная reservation по текущей таблице равна
`64 000 × 0.077 / 1 000 000 + 8 000 × 0.31 / 1 000 000 = $0.007408`.
Двести таких попыток — $1.4816. Это расчёт при заданных пределах и тарифах,
а не измеренное списание и не обещание закончить задачу за 200 попыток.
Если известный класс записи дороже обычного входа, резерв использует самую
высокую известную входную ставку. Неизвестный TTL нельзя включать в реальном
запросе, выдавая эту сумму за его потолок.

### Начальная сессия DSH и переход к перехвату вызовов

Подключение адаптера выполняется в уже существующем DSH. Первый запрос, которым
владелец передаёт директиву модели, может быть оплачен до появления этого адаптера.
Репозиторий не контролирует его задним числом. Поэтому запуск состоит из двух фаз:

1. **Ограниченная начальная сессия.** Исполнитель изучает фактически установленный
   клиент, его настройки лимитов, окончательный usage и правила повторов. Для
   этой работы используются уже поддерживаемые проектом DSH или провайдером
   ограничения оплачиваемых попыток, полного входа/выхода и суммы. Наличие таких
   ограничений нужно наблюдать, а не выводить из значения в JSON neuro. Не
   придумывайте команды DSH и не запускайте неограниченный цикл для разработки
   собственного ограничителя.
2. **Работа через реальную точку отправки.** Небольшая вставка в существующий
   клиент выполняет описанный ниже контракт до каждого последующего оплачиваемого
   запроса и сверяет его окончательный usage. До проверки охвата вызовов и повторов
   статус реальной интеграции остаётся неподтверждённым.

Настройки и вставка должны относиться только к neuro. Не меняйте общие defaults
DSH, профили, текущие сессии или сервисы Friday и других проектов ради этого
подключения. Если нет пригодного перехвата или независимо действующего ограничителя
начальной работы, сохраните результаты локальной диагностики и назовите точный
блокер; очередная оплачиваемая попытка требует действующего ограниченного режима.
Это не причина требовать от владельца ручной разработки CUDA.

Расходы и оплаченные попытки начальной фазы входят в те же общие пределы сессии и
кампании. Предпочтителен штатный проектный лимит DSH/провайдера, который действует
сквозным образом в обеих фазах. Сохраняйте наблюдаемые начальные квитанции отдельно
от исходников. `BudgetLedger` **не имеет API импорта прошлых расходов**: нельзя
создавать фиктивные `reserve`/`begin_dispatch`, будто они предшествовали уже
совершённым запросам.

Если базы учёта ещё нет и начальные расходы/попытки достоверно установлены,
допустимо создать приватную runtime-policy с меньшим оставшимся денежным и
сессионным лимитом перед первым созданием базы. Храните её в исключённом из Git
runtime-каталоге, например под `artifacts/private/`, вместе с исходной политикой,
её хешем и квитанциями, объясняющими уменьшение. Передавайте этот файл явно в
`BudgetLedger.from_project` или CLI `--project`; публичный `configs/project.json`
не переписывается машинным расходом. Согласуйте все подлимиты с уменьшенным
остатком и сохраняйте выключенный fallback. Это отдельный выбор вызывающего
кода, а не существующая автоматическая функция ledger.

Если база уже существует, сохраняйте её, первоначальную policy и те же campaign/
session IDs; не создавайте замену и не сбрасывайте историю ради изменения лимита.
Неустановленный начальный расход остаётся неопределённым и не превращается в
нулевой. Без его учёта нельзя заявлять точный общий предел $5/$25. Изменение общего
баланса аккаунта также не доказывает стоимость именно neuro, когда параллельно
работают другие проекты; используйте привязанные к запросам квитанции, когда они
доступны.

### Контракт с вызывающим кодом

Публичный интерфейс предназначен для небольшой вставки в **реальный существующий
клиент**. Его API, endpoint и способ перехвата вызовов DSH пока неизвестны, поэтому
в репозитории нет HTTP-прокси или мнимого DSH-транспорта. `reserve` и `begin_dispatch`
ничего не отправляют. Статус `dsh_adapter_connected` остаётся `false`.

До одного оплачиваемого вызова:

```python
from neuroctl.budget import BudgetLedger

ledger = BudgetLedger.from_project(
    "artifacts/model-budget.sqlite3",
    "configs/project.json",
    "configs/model-prices.json",
)
reservation = ledger.reserve(
    campaign_id="initial-campaign",
    session_id="repair-001",
    reservation_id="repair-001-attempt-001",
    max_input_tokens=64000,
    max_output_tokens=8000,
)
permit = ledger.begin_dispatch(reservation["reservation_id"])
assert permit["dispatch_permitted"] is True
```

После этого именно вызывающий код отправляет **один** запрос существующим
клиентом, с зарезервированной моделью и реально применёнными ограничениями.
Возврат `begin_dispatch` разрешает только эту попытку; скрытые платные повторы
SDK/DSH должны быть выключены или получать отдельные reservations. Вход должен
быть посчитан после добавления системных инструкций, инструментов и результатов,
а ограничение выхода должно включать оплачиваемое reasoning. Иначе локальная
граница не знает верхней стоимости будущего запроса.

После получения полного финального ответа:

```python
settled = ledger.reconcile(
    reservation["reservation_id"], final_response, api_format="openai"
)
if not settled["reconciled"] or settled["overrun"]:
    raise RuntimeError("Stop paid work: usage needs reconciliation or exceeded its bounds")

totals = ledger.status(campaign_id="initial-campaign", session_id="repair-001")
```

`final_response` здесь — объект, который должен дать реальный клиент; этот
пример не выполняет сетевой вызов. Формат `openai` иллюстрирует семантику
`prompt_tokens`; он не объявляет текущий MiniMax route совместимым с этим API.
Фактический формат выбирается после проверки ответа провайдера. При потере
ответа вызывающий код передаёт `ledger.reconcile(id, None)`: это неизвестный
расход с сохранённым удержанием, а не доказательство бесплатной ошибки.

### Те же операции через CLI

Команды запускаются из корня репозитория. Общие параметры `--db`, `--project`,
`--prices` и `--output` ставятся **после `budget`, но до подкоманды**. Без явных
путей используются `artifacts/model-budget.sqlite3`, `configs/project.json`
и `configs/model-prices.json`. Ни одна из команд ниже не отправляет запрос модели.

Перед одной попыткой реального клиента:

```bash
python tools/neuroctl.py budget --db artifacts/model-budget.sqlite3 \
  --output artifacts/budget-reservation.json reserve \
  --campaign initial-campaign --session repair-001 \
  --request repair-001-attempt-001 --input-tokens 64000 --output-tokens 8000

python tools/neuroctl.py budget --db artifacts/model-budget.sqlite3 begin \
  --request repair-001-attempt-001
```

Между `begin` и `reconcile` вызывающий код выполняет ровно одну оплачиваемую
попытку. В `artifacts/final-usage.json` он сохраняет её полный финальный usage,
без текстов сообщений и секретов. Дальше:

```bash
python tools/neuroctl.py budget --db artifacts/model-budget.sqlite3 reconcile \
  --request repair-001-attempt-001 --usage artifacts/final-usage.json --format openai

python tools/neuroctl.py budget --db artifacts/model-budget.sqlite3 status \
  --campaign initial-campaign --session repair-001
```

`--format openai` — пример явно выбранной семантики, а не подтверждение API
конкретного реселлера. При отсутствии финального usage вместо `--usage` передаётся
`--missing-usage`. Нечитаемый или повреждённый JSON-файл также превращается в
неизвестный расход с удержанием и `receipt_read_error=true`.

Граница чтения строгая: дубликат ключа в любом объекте, `NaN`/`Infinity` и
слишком глубокая вложенность считаются повреждением документа, а не поводом
выбрать «последнее» значение. Такая же строгость действует на границе
нормализации Python-объекта: если документ дублирует счётчики и на верхнем
уровне, и внутри `usage`, копии обязаны совпадать. Расхождение или счётчик
только на верхнем уровне — неоднозначный документ (`invalid_final_usage`), а не
полный receipt.

Код выхода `reconcile` равен 0 только при завершённой сверке без превышения;
неизвестный итог или превышение дают 1. Отказ лимита, конфликт ID, повторный
`begin` и ошибочные аргументы дают 2. У `status` код 0 означает, что состояние
успешно прочитано; это не разрешение отправки. Проверяйте `campaign.blocked`,
суммы удержаний и итог одноразового `begin`. Удалить удержание ещё не отправленного
запроса можно командой `budget ... cancel --request ID`; после `begin` она
отклоняется. Создание нового ID необходимо для каждой платной повторной попытки,
но не обходит остановленную кампанию.

### Состояния и перезапуск

| Состояние | Денежный учёт и допустимое действие |
|---|---|
| `RESERVED` | Полная сумма удержана; `begin_dispatch` разрешён один раз, либо `cancel_undispatched` снимает ещё не использованное удержание |
| `IN_FLIGHT` | Отправка уже разрешена; удержание не истекает, отмена не освобождает деньги |
| `UNRESOLVED` | Финальный usage отсутствует, повреждён, неоднозначен, неполон, не имеет цены или противоречит наблюдённым границам; удержание сохранено, новые reserve/begin всей кампании запрещены |
| `SETTLED` | Полный нормализованный usage оценён без скидки за кеш; удержание заменено рассчитанной суммой |
| `CANCELLED` | Отменён только неотправленный запрос; ID остаётся занятым и больше не разрешает отправку |

Повторный `reserve` с тем же ID и тем же намерением возвращает существующую
запись, не увеличивая расход. Изменить её модель, session/campaign или пределы
этим способом нельзя. Повторный `begin_dispatch` всегда отклоняется. Повторный
идентичный финальный usage идемпотентен; другой финальный usage у уже закрытой
записи отклоняется. Даже явно нулевой завершённый вызов занимает одну попытку.

После падения нужно открыть **тот же файл и те же идентификаторы кампании/сессии**.
Reservations и `IN_FLIGHT` сохраняются. Падение между `begin_dispatch` и реальной
отправкой тоже оставляет удержание: модуль не может доказать, был ли запрос
отправлен. Автоматического освобождения по возрасту или бесплатного повторного
использования ID нет. Запись `UNRESOLVED` можно позже закрыть полным подтверждённым
usage; до этого она блокирует новые отправки. Уже отправленные параллельные
запросы остаются учтёнными, и их ответы всё равно нужно обработать.

Численные пределы и тарифы закреплены в файле вместе с SHA-256 конфигурации.
Несовместимая правка не переоценивает прошлые вызовы и не расширяет бюджет
существующей базы. Явно переключать `fallback.enabled` можно без сброса истории:
его фиксированные подлимиты и общий расход сохраняются. Сам модуль не создаёт
новые кампании/сессии для обхода лимита. Не удаляйте базу и не меняйте ID, чтобы
продолжить остановленную автоматическую работу. Используйте локальную файловую
систему с рабочими блокировками SQLite; поведение сетевого диска здесь не проверено.

### Что является итоговым расходом

`settled_cost_usd` — консервативная оценка полного наблюдаемого usage по
закреплённой таблице. `quote_cost_usd` отдельно показывает арифметическую оценку
с указанными в таблице cache-ставками; она **не уменьшает бюджет** и не доказывает
фактический cache billing. При 64k входа, 2k выхода и 90% сообщённого cache read
MiniMax в ledger занимает $0.005548; таблица даёт условные $0.00199984.

`accounting_complete=false` у Anthropic не позволяет закрыть reservation, даже
при нулевых наблюдаемых токенах. Если неполный usage уже показывает больший
расход, удержание повышается как минимум до его обычной входной/выходной оценки.
Неизвестная цена конкретного класса cache write остаётся ошибкой сверки.
Отсутствующие OpenAI cache details допускают закрытие при полных input/output
итогах: кеш остаётся `UNKNOWN`, весь вход считается по обычной цене.

Наблюдённые нижние границы счётчиков хранятся в записи отдельно от резервации
(`observed_input_tokens`, `observed_output_tokens`) и не уменьшаются между
сверками. Полный receipt, сообщающий меньше уже наблюдённого, не закрывает
запись: она остаётся `UNRESOLVED` с кодом `contradicts_observed_floor` и прежним
или большим удержанием. Это не объявляет ошибкой любую меньшую итоговую сумму:
фактический полный usage может быть меньше резерва, а сама резервация использует
наихудшую известную применимую ставку. Скидка кеша settled cost не уменьшает.
Старый журнал без этих колонок открывается без потери истории: колонки
добавляются транзакционно, конфигурация и рассчитанная SETTLED-история не меняются.
Достоверные границы восстанавливаются из сохранённого нормализованного `usage_json`,
в том числе для `UNRESOLVED`; уже записанные границы только повышаются. Если старый
код уже перезаписал наблюдение, а сохранённого usage больше нет, восстановить его
по этой БД невозможно. Отсутствующие, повреждённые или неоднозначные данные не
выдумываются и не освобождают существующий UNRESOLVED/hold.

Если полный ответ превышает резерв или заявленные token bounds, ledger
**записывает всю рассчитанную сумму**, включая превышение $5/$25, и останавливает
новые отправки. Он не урезает стоимость до лимита и не скрывает отрицательный
остаток. Нарушение token bounds останавливает работу даже тогда, когда меньший
вход случайно компенсировал лишний выход. Исправить уже сделанный внешний платёж
локальная база не может. Известные тарифы, охват всех оплачиваемых попыток и
соблюдение запроса вызывающим кодом остаются условиями этой границы; дополнительные
неизвестные тарифы инструментов или провайдера в неё не включены.

В базе сохраняются непрозрачные ID, модель, пределы, числовой нормализованный
usage, ставки и коды состояния. Тексты запросов/ответов, API-ключи и заголовки
авторизации туда не копируются. Не помещайте секреты в сами идентификаторы.

## Проверка

Из корня репозитория:

```bash
python -m unittest discover -s tests -p test_cost.py -v
python -m unittest discover -s tests -p test_budget.py -v
```

Тесты стоимости проверяют двойной счёт кеша и reasoning, отсутствующие метаданные,
различие семантики OpenAI/Anthropic, раздельные TTL, неизвестные тарифы записей,
ошибочные числа и точность Decimal. Тесты бюджета запускают конкурирующие процессы
с общей базой, проверяют единственность dispatch, аварийный выход процесса после
разрешения отправки, сохранение удержаний, отдельные session/campaign/fallback
лимиты, повторную сверку и честный учёт превышения. Это синтетические usage и
реальные локальные транзакции. API-запросы не выполняются; тесты не объявляют
маршрут, кеш, внешний биллинг или DSH-интеграцию проверенными.

## Справочная документация о семантике API

Тарифы в этом файле происходят только из пользовательской таблицы. Для понимания
общей семантики кеширования полезны официальные описания, но их условия нельзя
автоматически переносить на реселлера:

- [Anthropic: prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)
  — раздельные счётчики входа, чтения и записи, отдельные TTL.
- [DeepSeek: context caching](https://api-docs.deepseek.com/guides/kv_cache/)
  — кеширование совпадающих префиксов и отдельные счётчики попаданий/промахов.

Остаётся проверить до платного запуска: провайдера и точный route, биллинг,
поддерживаемый формат usage, кеш в настоящем tool loop, лимиты контекста и
связь с установленным DSH. Текущая итерация этих подтверждений не подменяет.
