## Что сделано в коде

### Вычислительные проверки

`native/tests/cppminer_math_probe.cpp` сравнивает настоящий upstream
`Case33GemmXor` с независимым простым CPU-эталоном. Проверяются все промежуточные
XOR-результаты при K=4096, шаге128 и тайлах8x16: нули, знаковые границы, полные
границы INT8, границы накопительных этапов и прямоугольная матрица.

`native/cuda/mma_probe.cu` реализует четыре ограниченных запуска по одному warp
и две последовательные INT8 Tensor Core операции в каждом. Есть отдельный
CPU-эталон и проверка регистровой раскладки без GPU. CUDA-пробник собран и
слинкован под SM120, но на видеокарте не запускался.

### Управление экспериментами

`tools/neuroctl.py` предоставляет `doctor`, `source-check`, `cpu-check`, `cost`,
`run`, `compare`. Процессы запускаются без shell, с таймаутом и ограниченным
объёмом логов; результаты сохраняются атомарно. Проверки корректности, CPU,
GPU и pool evidence различаются. Неполные/синтетические данные не проходят
сравнение, а возвращаемый код процесса сам по себе не является доказательством.

### Стоимость

Поддержаны финальные usage OpenAI и Anthropic с разной семантикой cache counters.
Нет повторного сложения cache/reasoning tokens. Неизвестный кеш не получает
скидку; неполные или противоречивые данные не удовлетворяют проверке бюджета.
В независимом просмотре найдены и исправлены два случая некорректного учёта.

Реальные API-вызовы не выполнялись. Лимиты $5 на рабочую сессию / $25 на первый
этап сохранены как выбранная политика; её применение внутри DSH ещё не
реализовано. Офлайн-калькулятор не объявляется работающим ограничителем расходов.

## Что важно не перепутать

Upstream CUDA-реализация рассчитана на старые карты; её не следует объявлять
готовым быстрым ядром RTX50. В полном upstream build отсутствие Cargo приводит
к proof stub — такую сборку нельзя засчитать как успешную проверку доказательств.
Компонентная CPU-математика и две инструкции MMA не заменяют полный Pearl pipeline.
