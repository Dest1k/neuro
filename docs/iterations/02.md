# Итерация 2 / 10 — полный K=4096 и проверяемый transcript

Дата: 2026-11-11. Цель этой итерации — реализовать самостоятельный матричный
CUDA-компонент с полной длиной K и сохранением всех промежуточных XOR.
Владелец дополнительно попросил оставить корневой README совершенно пустым.

## Выполнено

- `README.md` оставлен файлом размером **0 байт**. Это требование закреплено
  в `AGENTS.md`; входные инструкции находятся в `state/current.json` и `docs/`.
- Добавлено CUDA-ядро K=4096, шаг milestone 128, пространственный XOR-тайл 8x16.
  Накопление INT32 сохраняется между всеми 32 milestone. Один warp обрабатывает
  участок 16x16 двумя MMA-инструкциями на каждый K32.
- Определён явный интерфейс A[M][4096], Bt[N][4096], transcript и необязательной
  полной финальной C. Размеры ограничены кратными 16 значениями от 16 до 1024.
- Созданы независимые Python-ожидания, C++-эталон с INT64 и CPU-эмулятор полной
  упаковки, MMA, XOR-reduction и scatter. Фиксированные данные и SHA-256
  сохранены в `native/fixtures/`.
- Добавлен GPU-пробник всех шести fixtures с двумя вариантами запуска:
  с выводом финальной C и без него. Результат — JSON и реальный код возврата.
- Новые проверки включены в `neuroctl cpu-check`, CMake/CTest и GitHub Actions.

## Граница готовности

В этой среде отсутствует GPU, поэтому реальное выполнение нового CUDA-ядра
не состоялось. Не проверены Windows, майнерная скорость, шум/commitments,
полный proof и принятые пулом shares. Компиляция и CPU-эмуляция не заменяют эти
проверки. Сейчас это ограниченный арифметический компонент будущего майнера.

Данные fixtures синтетические. Не подключены production scheduling, efficient
memory staging и host backend. Сначала нужен настоящий вход Pearl и корректное
прохождение его промежуточных стадий, затем измеряемая оптимизация.

Выбор модели и ценовая политика из первой итерации сохраняются. Внешние model
API здесь не вызывались; реальный cache billing и ограничение расходов в DSH
по-прежнему требуют отдельной интеграции.
